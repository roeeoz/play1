Choices and assumptions

  • Look and layout come from concept B: one centred card, progress dots, teal #0F766E primary buttons, full-width (standing brand rule). No product screen exists to copy; the font is the system stack, as no checkout ships a product font.
  • Desktop and phone are separate pages; the phone layout uses a body class, not media queries.
  • Invalid email shows the consent box ticked, so the email error is the only one on screen; consent missing shows a valid email, as Scenario 3 describes.
  • Field errors sit directly under their control, in red with an icon, and the control gets a red border; the submission failure is a banner above the button (structure's assumption).
  • Loading locks the inputs and Back as well as the button, so nothing changes while the submission is in flight; the button is not a link.
  • On submission failed the button reads “Try again” and leads, like “Subscribe”, to Confirmation; the cause is given as a problem on our side, since the visitor's input passed validation.
  • Error wording, the consent text and “We sent a welcome email” are proposals; the consent text needs legal confirmation before release.
  • The sample visitor is maya.cohen@example.com; the product is Halo and the newsletter “Halo Release Notes”.
