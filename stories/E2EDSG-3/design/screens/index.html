Choices and assumptions

  • Source: the page, the sidebar and the shell are rebuilt from src/halo/workspace/NewEpicPage.tsx and their stylesheets (NewEpicPage.css, HaloShell.css, HaloSidebar.css, index.css tokens), with the class names kept. Only the outline row, the confirmation and the filled description are marked as the change.
  • Font: the product's Assistant Variable is not in the checkout (no installed packages), so the pages fall back to the stack's system-ui.
  • Outline chips: one radio group labelled “Outline”, inside the composer behind a hairline, between the description and the attachment bar. The selected chip shows a tick on the light-blue fill, and a chip awaiting confirmation is dashed.
  • Headings: Markdown ## lines. New capability: Problem, Users, What they can do, Out of scope. Change to an existing screen: Screen, What changes, Why, Out of scope.
  • Own text: any edit to the inserted headings makes the text the PO's own, so picking another outline, Blank included, asks first. Keep my text (focused first) leaves the text and the previous outline; Replace text puts in the new headings.
  • Buttons: Replace text is outlined in the error red because it clears text, and Keep my text is neutral. Neither is a primary action, so the brand teal (#0F766E) rule does not apply here. Create epic keeps today's blue because the story doesn't change it.
  • Box height: a filled description is 230 px tall so every heading shows. Today the box is 110 px and would scroll.
  • Links: Blank and New capability go between the default and outline-selected pages, and the sidebar's New Epic opens the default page. Controls that lead to screens staying as they are today (Create epic, Cancel, the rest of the sidebar) and choices with no page of their own are drawn, not linked.
  • Not stored: only the description text is sent with the epic, as today. The chosen outline is not saved, so the API doesn't change.
