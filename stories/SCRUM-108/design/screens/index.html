Guestbook newsletter sign-up: all screens

Both screens in every state the structure names, each as a desktop page and a phone page. The look is the approved prototype's: a warm palette, a centred card and the teal primary button.

Choices made in this screen set
  • States: the inventory's form error is drawn once, with both inline errors showing (the case that shows the most). A name-only or email-only error is the same page with just that field's message. The structure's form-level failure is its own state, submit error. No empty states: the inventory marks them n/a.
  • Carried over from the approved prototype: the “Join the newsletter” label, the monthly-digest checkbox, the newsletter intro line, the confirmation copy and check icon, and the palette, type and spacing in tokens.css.
  • Brand rule: every primary button is teal #0F766E with white text (hover #115E59). While disabled for loading it is a lighter teal #6B9F9A, so it still reads as the same button. The button fills the card's width on every page.
  • Errors use the error red #B42318: a red border and pale red fill on the field, and the message with an icon under it, tied to the field with aria-describedby. The submit error is a role="alert" banner above the button.
  • Phone pages are laid out for a 390 px wide screen: the card sits at the top rather than centred vertically, padding is tighter (16 px page, 24 px card), the heading is 24 px and the button is a taller 48 px touch target.
  • Links: “Back to the guestbook” and the logo open this gallery, because there is no guestbook page yet (open branch 2; the real target is /). The buttons step through the states in flow order: default → error → loading. From loading, the two possible outcomes are linked in its row above.
  • Direct visit to Confirmation should send the visitor to the form (structure). That is a redirect, not a page, so it isn't drawn.
