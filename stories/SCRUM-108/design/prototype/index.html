Choices made in this prototype
  • Sizes: desktop browser at 1280×800 — the story names no device. The pages are responsive.
  • Main path only: Sign-up form → Confirmation. The inline name/email errors, the “Signing up…” state and the submit-error message from the structure are drawn in the next step.
  • Sample state: the form is shown filled in (Dana Levi, dana.levi@example.com) so the confirmation repeats exactly what was entered.
  • Join the newsletter (the button renamed from “Sign up”) is a link to the confirmation: the prototype has no script and sends no request (open branch 1 — where the sign-up goes — is still open).
  • Monthly digest: the checkbox under Email starts unchecked and can be ticked on the form. The confirmation shows the ticked variant with the line “You'll also get the monthly digest.”; when unticked that line is left out and nothing else changes.
  • Newsletter intro on the form no longer calls the newsletter a “monthly round-up”, so it isn't confused with the separate monthly digest.
  • Back to the guestbook (on both screens) opens this journey page: there is no guestbook page yet (open branch 2); the real target is a placeholder /.
  • Confirmation copy: “Thanks, {name}!” and “We'll send the newsletter to {email}.” from the structure, plus a check icon. The full name is shown as entered.
  • Primary button colour: the primary actions (“Join the newsletter”, “Back to the guestbook” on the confirmation) are teal #0F766E with white text (hover #115E59), per the brand rule. Links, accents and the arrows here keep the approved brick red.
  • Mobile: under 600 px wide the primary button stays full-width across the card, and the card's padding tightens so the button keeps the room.
  • Look: no guestbook UI exists, so one simple warm palette, a system font and a single centred card are used on both screens (tokens.css).
