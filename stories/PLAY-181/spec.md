## 1. סקירת הפיצ'ר

- **מה נבנה:** סקריפט Python קטן, `src/qa_20261111_s3.py`, שמדפיס את השורה "hello s3", ובדיקה אוטומטית ב-pytest, `tests/test_qa_20261111_s3.py`, שמאשרת את הפלט. הבדיקה רצה בשלב הבדיקות הרגיל של תהליך המיזוג. בנוסף נוספת שורה אחת תחת `## Unreleased` ב-`CHANGELOG.md` שמציינת את PLAY-181.
- **הבעיה:** האפיק "QA-20261111-S3 hello s3 script" נועד לוודא ששינוי זעיר בסיפור אחד עובר את כל שלבי פס הייצור — אפיון, פירוק, פיתוח ובקשת מיזוג — ונמסר בבקשת מיזוג אחת שכל בדיקות החובה שלה ירוקות, בלי לפגוע בבדיקות הקיימות.
- **המשתמשים:** המפתחים ומנהל המוצר שמתרגלים את פס הייצור (מסמך דרישות המוצר של האפיק, סעיף 1.2). מסמך הגדרת המוצר אינו מגדיר פרסונה.
- **סטייה מוסכמת ממסמכי האפיק:** מסמך דרישות המוצר (R1, R2) וצבר הסיפורים מציינים את הנתיבים `qa/qa_20261111_s3.py` ו-`qa/test_qa_20261111_s3.py` ו"בדיוק שני קבצים". שער המאגר של play1 (play1 layout gate) רץ על כל בקשת מיזוג ודורש שקוד Python יהיה תחת `src/`, שהבדיקות יהיו תחת `tests/` (כלל 1), ושתתווסף שורה ב-`CHANGELOG.md` (כלל 4). המפתח החליט לשנות את היקף הסיפור כך שיעמוד בכללים: הקבצים עוברים ל-`src/` ול-`tests/` (שמות `qa_20261111_s3` נשמרים), ונוספת שורת CHANGELOG אחת. כתוצאה מכך השאלה הפתוחה Q1 נסגרת: הבדיקה רצה בתהליך המיזוג מעצמה.

## 2. יעדים ומה מחוץ לתחום

### Story context

בתוך הסיפור: שני קבצים חדשים — `src/qa_20261111_s3.py` ו-`tests/test_qa_20261111_s3.py` — ושורה אחת תחת `## Unreleased` ב-`CHANGELOG.md` שמציינת את PLAY-181. מחוץ לסיפור: כל שינוי אחר בקבצים קיימים, כולל הגדרות הרצת הבדיקות ותהליך המיזוג, הסקריפטים הקודמים בתיקיית `qa`, פקודה מותקנת ו-`--help`.

### יעדים

- הרצת הסקריפט מדפיסה בדיוק `hello s3` ושורה חדשה אחת, בלי פלט לערוץ השגיאות, ומסתיימת בקוד יציאה 0.
- בדיקה אוטומטית שעוברת כשהפלט נכון ונכשלת בכל פלט אחר, ורצה מעצמה בשלב הבדיקות הרגיל של תהליך המיזוג.
- בקשת מיזוג אחת שכל בדיקות החובה שלה ירוקות, כולל שער המאגר, ושמשנה רק את שני הקבצים החדשים ואת שורת ה-CHANGELOG.
- הבדיקות הקיימות ממשיכות לעבור, ושלב הבדיקות מסתיים בפחות מ-60 שניות (play1 — goals and success metrics, G4).

### מחוץ לתחום

- כל שינוי בקובץ קיים מלבד השורה האחת ב-`CHANGELOG.md`. שורות קיימות ב-CHANGELOG, כולל שורת PLAY-175, אינן משתנות.
- שינוי בהגדרות הרצת הבדיקות (`pyproject.toml`), בתהליך המיזוג (CI) או בכללי שער המאגר.
- הסקריפטים והבדיקות של אפיקים קודמים בתיקיית `qa`, ובמיוחד `qa/20261110-s3/*` של האפיק הקודם באותו שם (RK2).
- פקודה מותקנת של הספרייה, תשובה ל-`--help`, ופונקציה ציבורית חדשה.
- רכיב תלות חדש.
- תיקיית התוכנית `stories/PLAY-181/`: היא תוצר של פס הייצור ואינה נספרת ברשימת הקבצים שהשתנו.

## 4. חוויית משתמש והתנהגות

- **הרצת הסקריפט:** המפתח מריץ `python src/qa_20261111_s3.py` ורואה שורה אחת, `hello s3`. אין שאלות, אין הודעות נוספות ואין שגיאות.
- **הרצת הבדיקות:** המפתח מריץ `pytest`, או ש-CI מריץ אותו בבקשת המיזוג, ורואה שהבדיקה החדשה עוברת לצד הבדיקות הקיימות. אם הפלט של הסקריפט ישתנה אי פעם, הבדיקה תיכשל ובדיקת החובה של בקשת המיזוג תהיה אדומה.
- **בקשת המיזוג:** מנהל המוצר רואה בקשה אחת שכל בדיקות החובה שלה ירוקות: שלב הבדיקות, ה-gate ושער המאגר. רשימת הקבצים שלה כוללת את שני הקבצים החדשים ואת `CHANGELOG.md`. אדם ממזג אותה אחרי סקירה. פס הייצור אינו ממזג.
- **פורמט הפלט:** טקסט פשוט, שורה אחת, בדיוק `hello s3\n`.

## 5. Acceptance Criteria

1. תרחיש 1: מסלול תקין — הרצת הסקריפט. **בהינתן** הספרייה עם השינוי, **כאשר** מריצים את `src/qa_20261111_s3.py` ב-Python, **אז** הפלט הוא בדיוק `hello s3` ושורה חדשה אחת, בלי שום פלט לערוץ השגיאות, **וגם** הסקריפט מסתיים בקוד יציאה 0.
2. תרחיש 2: מסלול תקין — הרצת הבדיקה. **בהינתן** הסקריפט כפי שנמסר, **כאשר** מריצים בלי גישה לרשת את שלב הבדיקות הרגיל של תהליך המיזוג (`pytest` בלי ארגומנטים), **אז** הבדיקה ב-`tests/test_qa_20261111_s3.py` נאספת ועוברת, **וגם** היא מסתיימת בפחות משנייה.
3. תרחיש 3: מקרה שגיאה — פלט שגוי. **בהינתן** עותק של הסקריפט שבו הטקסט המודפס שונה מ-"hello s3" (למשל "hello s4"), **כאשר** מריצים את הבדיקה, **אז** הבדיקה נכשלת.
4. תרחיש 4: רגרסיה — הבדיקות הקיימות. **בהינתן** הספרייה עם השינוי, **כאשר** מריצים את שלב הבדיקות הרגיל של תהליך המיזוג, **אז** כל הבדיקות שעברו לפני השינוי עוברות, **וגם** השלב מסתיים בפחות מ-60 שניות.
5. תרחיש 5: גבול התחום — היקף השינוי. **בהינתן** בקשת המיזוג של הסיפור, **כאשר** בודקים את רשימת הקבצים שהשתנו, בלי תיקיית התוכנית `stories/PLAY-181/`, **אז** היא כוללת בדיוק את `src/qa_20261111_s3.py`, את `tests/test_qa_20261111_s3.py` ושורה אחת שנוספה תחת `## Unreleased` ב-`CHANGELOG.md` ומציינת את PLAY-181, **וגם** אף קובץ קיים אחר ואף רכיב תלות חדש אינם משתנים או נוספים.
6. תרחיש 6: גבול התחום — מיזוג. **בהינתן** בקשת המיזוג של הסיפור, **כאשר** מנהל המוצר בודק אותה לפני המיזוג, **אז** כל בדיקות החובה שלה ירוקות, כולל שער המאגר, **וגם** תיאורה מציין את הסיפור PLAY-181 ואת מסמך הדרישות שממנו הגיע.
